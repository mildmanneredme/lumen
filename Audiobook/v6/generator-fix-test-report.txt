LUMEN Gemini generator fixes: offline regression report
Date: 9 October 2026
Production mutation: generate_audio.py and this report only.
All fake job files used isolated /private/tmp directories and were removed.
No API requests, credential access, generation, or production cache writes.

Implemented changes
- Requests cannot reuse attempts or receipts with a different request hash.
  New receipts include their own hash; legacy receipts require their matching
  durable attempt record.
- New requests reserve the full maximum charge under LOCK before dispatch.
  The durable ledger is the sole reservation counter, so active requests are
  counted once. Dispatch requires the reservation's unique ownership token.
- Cached WAV bytes must match audio_sha256. Legacy metadata lacking that hash
  can be rebuilt locally from a bound receipt without a new paid request.
- Explicit daily/per-day quota errors stop after one HTTP 429 response.
  Transient 429 retries and rejected-before-generation resumption remain valid.
- Attempt/receipt JSON persistence now fsyncs the temporary file before rename
  and fsyncs the containing directory afterward. Failed persistence prevents
  dispatch; uncertain billing remains conservatively reserved and blocked.
- Empty WAVs are rejected before calculating pace.

Independent final review
An independent reviewer ran 29 additional isolated mocked tests against this
final source. All passed, including receipt recovery after disk-write failures,
exact reservation ceilings with concurrent requests, single-ID dispatch
suppression, and file-fsync -> rename -> directory-fsync ordering before
dispatch. File/directory fsync failures both prevented requests. No remaining
defect was found within the confirmed single-generator-process scope.

Combined result: 46 offline tests passed (17 below + 29 independent).
Read-only compatibility check: all 11 existing receipt/metadata pairs matched
the current request hashes, and all 11 cached WAV audio hashes matched. No
production cache, receipt, attempt, or generation manifest was changed.
LOCK coordinates worker threads in one process; run one generator instance.
